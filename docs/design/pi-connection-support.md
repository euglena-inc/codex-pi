# Pi connection support

## Outcome and sequencing

Add opt-in explicit proxy routing and privacy-safe transport diagnostics to the canonical plugin, then continue the already-authorized instruction clarity pilot. The pilot remains a separate task with its original sessions, deadlines and trial budget. Do not edit its frozen helpers or raw evidence. One Pi implementation worker runs at a time. This task changes plugin transport support, not provider/model policy or experimental outcomes. Publishing, plugin installation and global Pi/system proxy changes are outside scope.

Observed evidence: an original-path Pi request failed with ECONNRESET before TLS establishment. Ten small explicit-proxy tool round trips completed, but a longer implementation session later failed with proxy CONNECT 503. This supports an explicit configurable route plus actionable diagnostics; it does not establish that a proxy fixes all failures. Pi's existing automatic retry is disabled locally. Do not enable automatic retries, silently switch routes/models, replay tools or hide failed requests in this change.

## Design

Add optional project config `network` with only `proxyUrl` and `diagnostics`. `proxyUrl` is an explicit credential-free http/https proxy URL; reject userinfo, query, fragment, invalid/missing host or port, unsupported schemes and non-root paths without echoing the supplied value. `diagnostics` is boolean, default false. Omission must preserve current inherited environment behavior and old task compatibility. There is no hardcoded localhost port or automatic OS proxy discovery. Existing proxy environment variables remain usable when no explicit URL is configured.

Validate configuration before task side effects. Freeze the optional policy in new task metadata and use that frozen policy for continue, independent of subsequent project edits. Old tasks with no network policy keep current behavior. Apply explicit HTTP_PROXY and HTTPS_PROXY to the Pi process environment, consistently override conflicting lowercase/all-proxy forms for explicit routing, and preserve intentional NO_PROXY exclusions with documented semantics. No global settings/auth changes; never copy credentials. Child tool processes inherit the same network policy. Supervisor transport to Codex queue must not accidentally be rerouted by this Pi-only setting.

When diagnostics is enabled, install a small dependency-free Node preload observer using `node:diagnostics_channel` for undici request events. Include it in helper snapshots and recovery handling. Wire it via process-local NODE_OPTIONS with correct quoting/path handling and preserve existing options. Do not replace fetch or dispatcher, modify requests, or turn response-stream cleanup AbortError into a failed provider call. Diagnostics must work with Pi's bundled CLI, which replaces global fetch. Cover pre-header ECONNRESET, timeouts/DNS failures, proxy CONNECT status errors, and genuine post-header errors conservatively; unknown is unknown. No claims of model outage based on a connection event.

Write bounded per-round private structured diagnostics to a dedicated sidecar, not stdout/protocol JSON. Store only allowlisted fields: relative timestamp/duration, event phase, safe classification, allowlisted error code, HTTP or CONNECT numeric status. No body, headers, URLs, hostname, query, keys, raw exception text, prompts or session payload. Ignore normal abort cleanup; diagnostics write failure must never break the model call. Event count/bytes are bounded; signal truncation without inventing full coverage. Concurrent inherited children must not corrupt records or make misleading attribution; use a safe process-local identity if needed, with clear scope. Disabled mode produces no diagnostic file/preload behavior.

Expose a compact redacted network policy/source and diagnostic file reference in appropriate existing status/result evidence, not full logs or raw proxy credentials. Classifications remain observational, never acceptance; a process exit of zero with model error remains execution failure. A task with missing diagnostic file is unknown, not healthy. Keep public output small and retain existing fields/contracts.

Document one portable configuration example using a synthetic address, environment fallback and precedence, enable/disable behavior, and remediation: pre-TLS reset points to transport; CONNECT 503 identifies proxy tunnel failure; validate/switch the user-configured proxy route explicitly, never promise permanent repair. If the route fails, preserve session and resume explicitly after recovery. Native Pi retry configuration is separate and should not be modified by this plugin.
