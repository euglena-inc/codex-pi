# Outcome metrics: small, source-backed delivery observations

## Outcome and boundary

Deliver 0.8.5: extend the existing metrics CLI with a main-owned closeout record and a read-only outcome view. Reuse task metadata, stored round summaries, receipts, network diagnostics and exact board decisions. Keep existing metrics fields and execution APIs compatible. No new model calls, service, dashboard, scheduler, acceptance gate or transcript mirror. A closeout is a reported observation, never a phase acceptance, ownership decision or permission to execute.

This resolves a demonstrated gap: Pi can fail execution while Main later delivers the result, and Main's supplemental checks/costs are outside the Pi summary. Keep both facts. Runtime algorithms and all frozen acceptance, budget, model and takeover rules remain protected.

## Minimal interface and persistence

Add `pi_board.py record-outcome --repo REPO --outcome ID --record-file FILE [--expected-revision N]` and `pi_board.py metrics --repo REPO --outcome ID`. Also allow a bounded cursor listing of recorded outcomes through `metrics --outcomes`; keep existing task metrics behavior unchanged. Use a focused lower-level metrics module if needed for the existing module-size/dependency contract; preserve the existing `pi_board.task_metrics` import API and freeze any new helper in new task snapshots.

Store bounded versioned JSON observations under the existing private git-common `codex-pi/outcomes/<ID>/` directory. Reuse existing locking/atomic-file primitives. No new database. Full snapshots are immutable numbered revisions; no mutable copy of execution state. The latest valid revision is the observation being queried. Initial revision expects zero; corrections require the current revision and retain older snapshots. Identical normalized payload replay is idempotent, including an uncertain write retry. Conflicting/stale updates fail without changing files. Hold one local observation-write lock around compare-and-publish. Missing/corrupt history or an ambiguous latest record is an error/unknown, never a guessed winner. Validate IDs and resolved paths; no traversal, symlink escape or credential/transcript copying.

Record schemaVersion 1 with these fields:

- `members`: explicit list of `{task, rounds: [positive integers]}`. Require real tasks/rounds in the same git-common directory at write time; reject duplicate task/round memberships. Flatten only these references, never infer a predecessor from names or recursively follow other outcomes. Empty members supports explicitly recorded Codex-only work. Referenced source later missing/corrupt makes metrics incomplete. Preserve failed attempts and model switches in the selected membership; corrections remain auditable.
- `status`: accepted, partial, failed, cancelled or unknown. `candidate` is a full real repository commit for accepted results; optional otherwise. `evidenceRefs`: bounded explicit reference strings, required for accepted reports. Mark these as Main-reported references, not automatically verified acceptance. Do not read arbitrary evidence contents or infer results from prose.
- Optional `startedAt` and `finishedAt`: finite nonnegative Unix seconds with a valid ordering. They are Main-reported boundaries. Without an explicit start use the earliest known member task creation time and label it dispatch scope, excluding prior planning. Without an explicit finish keep true delivery latency unknown; expose observation `recordedAt` separately, never substitute it for actual acceptance time.
- Optional `work`: bounded entries with unique `id`, a `kind` from design/review/debug/supplemental_checks/takeover/other, optional actor/model, optional start/end timestamps, optional usage (`input`, `cacheRead`, `cacheWrite`, `output`, `totalTokens`) and optional `reportedCostUsd`, plus `evidenceRef`. These are externally reported work, not inferred by reading Codex conversations. Missing numeric fields stay null. Require source references for supplied quantities. Optional `workComplete` is a Main declaration of external coverage; default false and label the declaration.
- Optional `extraChecks`: paths to existing standard pi_check receipt JSONs relative to the private git-common codex-pi root. Resolve within that root, read bounded metadata and pin its SHA-256 at recording. Never copy or read large raw logs just to calculate statistics. This admits Main supplemental check receipts without pretending Pi ran them. At query time metadata mismatch/missing files are unknown. Deduplicate a receipt referenced by a round summary and by extraChecks.

Reject unknown fields, booleans as numbers, negative/non-finite quantities, fractional token counts, bad timestamps, unsafe paths and oversized input. Record canonical payload digest, revision and server recordedAt separately. Numeric zero is valid recorded data; an absent field is not zero. No record command may alter task/round/helper files, board decisions, review counts, ownership, pause, budgets or queue delivery. Metadata collection/read errors cannot cause any worker or model call.

## Read-only projection

Expose six compact sections with source/scope and known/partial/unknown coverage. Calculate on explicit metrics requests from bounded metadata; ordinary board refresh must not scan all outcomes or sessions.

1. Delivery: the Main-reported status/candidate and native execution/quality facts are separate. Show exact native accept/reject/change decisions for the selected rounds, and first reviewed delivery acceptance only where a genuine decision exists. No quality decision means unknown, not an invented failure. Fetch archived decisions/events through existing cursor readers rather than only the visible card window.
2. Timing: reported/deduced start, reported finish, elapsed wall time, and union of known round execution intervals. Model/tool/check intervals can overlap and checks are inside tools. Give sums only as explicitly labelled work sums; do not add them to obtain wall time. Review wait may be derived from valid event-created/handled intervals with coverage; missing information remains unknown. Explicit external work intervals are reported separately. Never infer active Codex reasoning time from silence or elapsed wall time.
3. Rework/incidents: distinct reviewed quality failures, recorded failed check attempts, failed/unknown rounds, observed transport errors and native takeover cause. Separate transport events, ordinary check failures and quality rejections. Do not label tool calls or new rounds as new complete deliveries, or infer semantic repair counts.
4. Verification: metadata-backed check counts, completed elapsed work and interval union; group clean checks by exact candidate plus normalized argv to show potential repeats. Unknown inputs/environment mean these are potential repeats, not proven waste. No automatic classification of a command as full regression by its name. References alone are not a new execution. Label capture as recorded-check coverage; uninstrumented checks remain outside it.
5. Usage/cost: retain actual frozen/reported model identities; aggregate recorded assistant and auxiliary usage once, with reasoning already in output. Do not silently assign mixed/mismatched model totals to the configured model. Keep known Pi portions and external reported portions separate; combine reported cost only with valid complete source coverage and declared external completeness. Billing remains unverified, and output bytes are never Codex tokens. Missing/legacy/invalid sources stay explicit. Use the existing aggregation logic where possible.
6. Intervention/coverage: known Main work entries, native takeover evidence and missing external coverage. A takeover plus final accepted report must remain visible as assisted/Main completion. Absence of work records is not proof of no intervention.

A listing is a bounded view of recorded observations, not a complete denominator of all work. Expose membership and missing-source coverage; do not publish success rates or strategy savings from a selectively recorded cohort. Retain legacy task metrics so failed or unrecorded work remains inspectable. Do not auto-import historical private Main reports by guessing their shape.

Arithmetic controls: rounds [0,10] and [5,15] have 15 seconds of execution union, not 20. Checks [2,8] and [5,9] have 10 seconds of work but 7 seconds of wall coverage. The same source cited twice counts once; two distinct clean executions with the same head/argv can be marked potential repeats without calling either waste. A failed Pi run plus an explicitly reported accepted Main candidate is successful reported delivery with preserved failed execution, never rewritten Pi success.

## Delivery and verification

One implementation outcome includes CLI/storage/projection wiring, focused meaningful tests, usage documentation/examples and 0.8.5 metadata/version assertions. Keep logs, real task IDs, work records and receipts outside tracked files; synthetic fixtures only in public tests. Main will create a real retrospective observation from the already accepted 0.8.4 facts only after candidate verification, labelling its sources and incomplete external cost.

Use tests/test_outcome_metrics.py for record/query behavior: actual CLI round trips, immutable/idempotent revision handling and stale conflicts, malformed/oversized inputs, path escape, duplicate membership/source references, legacy/missing/corrupt data, cross-task/round grouping, overlaps, repeated checks, partial costs and preserved failures. Demonstrate no board/execution mutation and no raw-session scanning on metrics/refresh, plus archived decisions beyond the projection window. Preserve existing metrics tests. The targeted module is the debugging entrypoint. Final integration runs the full Python suite once because CLI/helper snapshot and archive-backed reads touch shared lifecycle wiring, then privacy and whitespace checks. The frozen budget is 5400 seconds with serial checks and 900 seconds per command. All required failures remain evidence; same-session repair or explicit takeover follows the existing policy.
