# Necessary verification and isolated test environments

## Outcome

Deliver a coherent 0.8.4 upgrade that selects verification by actual behavioral impact, preserves applicable original evidence, and fixes the reproduced inherited-diagnostics failure in synthetic tests and validation tools. Use the existing contracts, receipts and acceptance flow. No automatic test router, dependency analyzer, cross-version PASS cache, receipt import system or additional approval/reporting layer is needed.

Baseline: 0.8.3 (`a2194fd`). Two existing tests reproduce the defect in under a second with a synthetic parent diagnostics identity and a different-path copy of the preload: the disabled-diagnostics integration test inherits a nonempty sidecar target, and the synthetic classifier sees duplicated events. The source and private failure logs are retained by Main. Production network behavior did not change in the preceding policy release.

## Settled design

Verification selection belongs to the main model before contract freeze. Development checks the reproduced failure and affected behavior; delivery checks the outcome and its actual consumers; independent review inspects original receipts and only reruns for coverage, applicability or authenticity concerns. Full regression is reserved for a justified broad integration boundary. A new commit, round, reviewer or release label alone is not a reason for full regression. Inspect existing wrapper composition so an enclosing command's child checks are not redundantly rerun. Use cheap existing prerequisites before slow dependent work.

Human-only prose changes need appropriate format, JSON and reference validation. Model-visible instructions, tool schemas and startup/generated artifacts can affect behavior despite their file extension: review the relevant semantics and assembly, with bounded live comparison only when a model-capability or strategy-benefit claim requires it. Do not add tests that merely match instruction wording or run real model experiments for deterministic environment correctness.

Reuse original evidence only where covered behavior, relevant source/assembly, dependencies, inputs, environment and evaluator remain applicable and no relevant failure contradicts it. Cite the original receipt, candidate and log with a short current-applicability reason in existing review records. Retain original identities and failures. A contract's required failed command still needs the promised successful evidence; a weaker local test cannot substitute. Current readiness only consumes current-round exact-candidate receipts. Explain this limit honestly: select necessary new commands at freeze time and reference unchanged component evidence in Main review, without pretending the runtime supports automatic cross-round/head reuse. Keep exact head/argv/ID/log/timeout validation and all active frozen helpers unchanged.

Use the existing contract default: when `checkId` is omitted it equals `id`. Recommend that default, or identical literal values when explicit. If a deliberate distinct `checkId` is used, the brief must name the exact tool ID. Do not add case folding, aliases or a schema migration. `targetedCommand` is a local debugging suggestion for an already declared formal command; it does not require every outcome to include a full-suite command or require a redundant targeted run when applicable evidence is already available.

Fix environment isolation at the test/validation subprocess boundary. Prefer one small reusable helper in existing test support: copy the supplied/ambient environment, remove inherited `NODE_OPTIONS` and the three plugin diagnostic identity variables, then apply explicit fixture overrides last. An isolated synthetic fixture must opt into Node flags/preloads and diagnostic identity deliberately. Preserve unrelated environment values, do not mutate `os.environ`, do not remove explicit overrides, and do not disable diagnostics being intentionally tested. Integrate the helper with existing Pi test environment construction and diagnostic probes, including the standalone connection validator's real entrypoint. It is acceptable for that validator, which already depends on the test suite, to reuse test support. Avoid broad speculative environment rewrites, custom NODE_OPTIONS parsers, user-path/model-name special cases and production network changes.

## Scope and verification

Pi owns one complete outcome: active guidance alignment, fixture isolation, meaningful regression coverage, release metadata/version assertions and a clean candidate. Main owns this frozen design, review and local integration/installation. Allowed changes include AGENTS.md, active collaboration guidance/references, README/implementation notes, existing test helpers and affected tests, the connection validation script, and release metadata. Runtime algorithms, model configuration, providers, production environment policy, hooks/queue, budgets, ownership and receipt acceptance are protected. Mark obsolete delivery-specific designs historical only where an active reference would otherwise mislead; retain their evidence. Keep this design unchanged in the worker.

First use the connection-support tests and new focused isolation controls. Cover a normal caller and a synthetic inherited worker environment, a different-path preload with spaces, actual Node/CLI behavior, exactly one intended observer rather than zero or duplicates, disabled-sidecar behavior, explicit diagnostic/Node overrides, unchanged unrelated variables and unchanged parent environment. Preserve existing enabled-diagnostics, privacy, limits and failure assertions. One bounded negative control against the old isolation behavior must remain observable; do not turn a failing assertion into a conditional skip. Use synthetic paths/identities and clean all fixtures.

For final acceptance, run one full Python suite on the clean candidate because the shared fixture helper affects many test callers. The suite must include the focused isolation coverage; do not additionally rerun every constituent module. Verify the standalone connection validator with `--no-integration` so its entrypoint is checked without nesting the full connection unittest module again. Run privacy and whitespace checks. The frozen contract names identical acceptance/check IDs and bounds the task to 3600 seconds with serial checks and a 900-second command cap. Required failure repair remains in the same session and budget. Main reuses valid exact-candidate receipts instead of automatically repeating the suite.

Release completion requires independent semantic and scope review, verified original receipts, local integration and formal plugin installation with version/file identity verification. Policy simplification is not proof of model speed or savings; retain all implementation failures and external assistance. This outcome does not authorize public push, new business-project experiments or edits to managed caches.
