# Worker 效率优化：完整路线

本路线承接用户授权的六项优化，按实际依赖推进。目标是减少无效启动、重复检查和上下文往返，同时保留原始失败、不可变回执和完整最终验收。所有实现优先复用现有机制；不新增服务、数据库、通用工作流引擎或业务项目专用逻辑。

## 1. 检查预算与局部修复（已设计，Pi 实施中）

准确设计和验收见 [check-budget.md](check-budget.md)。先交付预算准入与 targetedCommand/final 检查语义，随后在同 task/session 的安全轮次边界 adopt-runtime，实际验证两类拒绝、局部检查和完整最终验收。该阶段运行中的 brief/helper/合同不追加修改。其独立交付通过后继续本路线，不能将该阶段完成称作六项全部完成。

## 2. 廉价前提先核实（后续实施）

在现有协作设计/任务包模板中，要求明确：准确候选/工作树、必要工具和资源可用、所需受限输入由谁提供及如何被可信检查读取、历史断言与已接受变更如何对账。只核任务真正需要的前提，不加泛化preflight服务或固定清单门槛。

复用现有 check 执行消费项目实际提供的廉价命令；没有可执行前提检查时如实标注。前提失败时停止依赖它的昂贵检查并保留原证，不将前提通过计为正式验收。合同 preconditions 当前是文本，不对外宣称已自动执行。用合成任务证明“廉价失败→不启动昂贵子进程；修正输入→原昂贵检查真实执行”。不自动读取封存题、复制受限业务输入或给它们扩大路径权限。

## 3. 时间和 token 分解（后续实施）

在 pi_summary/board metrics 现有输出增加紧凑分项，复用原始消息、检查回执和轮次元数据。token 只按唯一 assistant 最终 usage 汇总；reasoning 是 output 的子项，compaction 的额外 usage 单独标识后按 Pi 实际语义计入，不重复累计 agent_end/turn_end/流式 delta。

报告未缓存输入、缓存读取、输出、缓存比例、每请求上下文的首/末/峰值、模型响应时间、工具时间、未结束检查及无法归因的余量。时长按区间并集处理并发和 codemode 父子调用；不得累加父子时长形成超出墙钟的总量。优先利用已有 session 写入时间与消息 timestamp；缺精确时间时明确 estimated/unknown，必要时才给未来轮次增加轻量单调时钟事件，不改历史日志。费用保持 reported 而非账单承诺。

历史读取限量、分页/按轮次，普通 board 刷新不重复全量扫描；私有原文不塞入通知。验证串行、并行、嵌套、截断/运行中、无usage、compaction，以及历史记录兼容。将本任务作为真实样本核对总量和时间，不记录虚构节省。

## 4. codemode 的有效批处理（已有能力，后续优化用法与验证）

0.7.0 已启用原生混合模式、关闭辅助 models、保留逐调用守卫。本项优化短指引和真实使用验证，不重复实现 sandbox。将独立读取/搜索/日志筛选合并为短脚本，输出必要结论与原证引用。不要批量隐藏失败、无界积累结果、并行依赖写入，或在未隔离数据库/端口/容器的前提下并行测试。长检查受第1项外层/内层预算共同约束。

用固定的合成文件和等价目标做直接调用/批处理对照：比较实际模型往返、工具输出体积、用量与墙钟，同时核相同内容、失败可见性和守卫效果。无可信等价对照，不声称百分比优化，也不强制所有简单调用通过 codemode。

## 5. 安全边界的原生压缩（先验证，再决定自动化程度）

只复用 Pi 原生 compaction/session 接口，不删会话、换 task/session、改质量计数或自建摘要状态库。先在合成会话验证：压缩前后 task/session identity、完整原始记录、失败回执、当前候选与缺项、store恢复、模型 pins、预算和未来轮次采用保持一致；失败/取消仍诚实。摘要必须引用原证而非替代验收，不能把复杂合同和已拒绝事项压成失真通过结论。

计入压缩本身的模型费用和耗时，并观察其对缓存前缀的影响。初版优先提供安全边界的显式调用或建议；只有测试和受控真实试验支持时，才在工具空闲、预算足够且确实需要时自动调用。不得仅因上下文数字大就盲目频繁压缩，不引入新模型或提高现有任务预算。验证不支持自动启用时交付已验证机制/限制和准确结论，不以关闭功能冒充压缩优化完成。

## 执行顺序与完成标准

先完成第1项（对应六项清单中的预算准入、局部优先两点）及其自用验收，再在准确接受的候选上冻结后续完整成果：廉价前提用法+统计，然后批处理对照+原生压缩安全验证。沿Codex-Pi执行，依赖未接受不提前派工；每段仍受原两次完整交付/接管规则约束。

后续实现前读取新候选的相关源码，补齐实际 API、边界和可执行验收命令，不将本路线的尚未验证接口当作已知事实。每段完成后更新真实状态与脱敏验证说明；最终交付列出六项各自实现、证据和限制。此授权不含推送、发布、重装插件、给其他聊天发消息或改动其活动worker；需要发布时依据当时用户授权处理。
